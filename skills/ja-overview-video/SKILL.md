# 日本語・無音の Devin 概要動画を作る

複数の機能を「何ができるか」の流れで見せる短い紹介動画を作ります。1 つの機能を手順どおり見せる場合は `ja-devin-feature-tutorial` を使ってください。

## 最初に決めること（依頼に無ければ聞く）

- 見せる機能と順番（例: 解析 → 移行 → テスト → レビュー）
- 見た人に持ち帰ってほしいこと（1 文）
- 使うデモリポジトリ（例: `natt-cog/Usagi-Bank`）と OS（Linux / macOS / Windows）
- 参考ドキュメントのリンク（docs.devin.ai）

## 固定の方針

- **言語:** 画面上の文字（タイトル、章カード、字幕、早送りバッジ、エンドカード）はすべて日本語。製品名・ボタン名は画面の表記どおり（例: 「Ask Devin」「Devin Review」）。
- **音声なし:** ナレーション・BGM・効果音を入れない。`build.sh` は既定で無音。書き出し後に `ffprobe` で音声ストリームが無いことを確認する。
- **画面中心:** 図解（`scene:`）は最小限。各機能の前に章カードを置き、そのあとは実際の Devin の画面で見せる。
- **新規録画:** 毎回新しく録画する。過去の動画や PR の録画は使わない。
- **見た目:** 明るい `#fafafa` 背景、白いカード、細い青のアクセント、Noto Sans JP。暗い背景・紫・派手な文字演出は使わない。
- **アカウント:** Natt の組織（natt.devinenterprise.com）と `natt-cog/*` のリポジトリで録画し、メールアドレスは `MASK_TEXT` で隠す。

## 正確さのルール

- 最新の公式ドキュメントと実際の製品の動きを確認してから台本を書く。無い機能・設定・上限・保証を作らない。
- 画面で見せる結果はすべて本物にする。偽のスクリーンショット、図を本物の動作の証拠として使うこと、テストしていないものを「合格」と書くことはしない。
- わざとバグを仕込む場合は事前に Natt の許可を取り、字幕で明示する。失敗→修正→再テストは実際に起きた場合だけ見せる。
- 順番（時系列）を隠したり入れ替えたりしない。

## 構成（目安）

1. タイトル（`SPEC.title` / `subtitle`）: 何の動画かを 1 行で
2. 章ごとに「章カード → 実画面 2〜5 カット」。章は 3〜6 個
3. エンドカード（`SPEC.outro` / `outroSub`）: 動画で見せた内容を短くまとめる。宣伝文句は使わない

長さは 1 章 20〜40 秒、全体 60〜180 秒が目安。

## 字幕の書き方

- 1 カット 1 行、30 文字前後まで。画面で起きていることをそのまま書く（例: 「Devin が COBOL のコードを読み、処理の流れを説明します」）。
- です・ます調。「革新的」「シームレス」「魔法のように」などの宣伝語は使わない。
- 操作中の部品や読ませたい文字を隠さない。設定画面やメニューでは `capPos: 'auto'` と `target` で部品の近くに置く。セッション画面では入力欄にかからない下部に置く。
- 表示時間はキットが自動計算（日本語 1 秒約 8 文字）。短すぎる場合は `hold` で延ばす。

## 章カード

`beats.json`（`r.shot({chapter: ...})` など）か `spec.js` の `edit` で、章の最初のカットに付ける:

```js
"0012.png": { "chapter": { "title": "COBOL から Java へ移行", "sub": "新旧の出力が一致することをテストで確認", "short": "移行" } }
```

- `title`: 機能名（15 文字前後）。`sub`: 何を見せるか（30 文字前後）。`short`: 下部の章一覧に出す短い名前（2〜6 文字）。
- 表示時間は既定 3.4 秒（`hold` か `SPEC.chapterHold` で変更）。章一覧を消すときは `SPEC.chapterList = false`。

## 編集（見やすくするための早送り・間の調整）

- Devin が作業している待ち時間は 2〜2.5 秒程度に詰め、無操作は 3 秒以内。`speed`、`pollRunMax: 2.2`、`skip`、`hold` を使い、詰めたカットには `"badge": "早送り"` を付ける。
- 大事なメニュー・選択状態・ダイアログは 2.5〜3 秒見せる。不要なら切る。
- プロンプト入力は `cps: 48` 程度。3 秒を超える長さなら入力済みの静止画にする。
- 枠（リング）は細い青 1 つだけ。対象が表示されてから出し、`ringFor` で長く残さない。
- セッション内は画面全体が見えるようにし、過度なズームをしない（`noZoom`）。読み込み中の画面、通知、「Take control」などが写ったカットは使わない。
- 転換（章カードとカメラ移動）は 30fps 以上で確認し、カクつきや飛びが無いようにする。

## 録画

- Chrome を CDP（`127.0.0.1:9333`）付きで起動し、Natt の組織にサインイン済みであることを確認する。サインインが切れていたら Desktop タブでのサインインを依頼する。
- ライトモード、ブラウザ倍率 125%（`ZOOM=1.25`）。使わないときは左サイドバーと右パネルを閉じる。
- 録画前に通知・バナー・古いセッションが写らないか確認する。関係ないセッションは `HIDE_TEXT` で隠す（デモの状態を変える目的では使わない）。
- 長い作業はフェーズ（`PHASE=ask` / `work` / `test` など）に分け、途中から撮り直せるようにする。
- 新しく撮ったカットは `shots/SOURCES.json` に、セッション URL と何を証明するカットかを記録する（認証情報は書かない）。

## 書き出しと確認

`videos/` で実行:

```sh
node _kit/tools/render.mjs <folder> --count
node _kit/tools/render.mjs <folder> --frames <リスト> --out build/fix   # 字幕・章カード・転換を静止画で確認
bash _kit/tools/build.sh <folder>                                      # <folder>.mp4（4K60）と <folder>-1080p.mp4
ffprobe -v error -show_entries stream=codec_type,width,height,r_frame_rate -of csv=p=0 <folder>/<folder>.mp4
```

確認すること: 日本語が豆腐（□）や崩れになっていない、字幕がはみ出さない、クリック位置と字幕が一致、章カードの番号と章一覧が正しい、音声ストリームが無い、3840×2160・60fps。

## 納品

- `natt-cog/devin-demo-videos` の最新 `main` からブランチを切り、`videos/<NN>-<slug>/`（`capture.mjs`、`shots/`、`spec.js`、MP4、`poster.png`、`README.md`）と、ルート `README.md` の一覧への追記を 1 つの PR にまとめる。
- 大きい MP4 は別コミットで push する（1 回 300MB 程度で失敗することがある）。ビルド用フレームや秘密情報はコミットしない。
- PR の説明に 1080p 版の動画（アニメーション WebP に変換して埋め込む）と主要な静止画を入れる。デモ用アカウントで作ったセッション・PR など、残っている後片付けも書く。
- Natt の許可なくマージしない。チャットには PR リンク・長さ・1080p 版を送る。
