# 日本語・無音の Devin 機能チュートリアルを作る

1 つの機能を、きれいな初期状態から目に見える結果まで手順どおりに見せる動画です。複数の機能をまとめて紹介する場合は `ja-devin-overview-video` を使ってください。言語・音声なし・見た目・正確さ・字幕・章カード・書き出し・納品の共通ルールは `ja-devin-overview-video` と同じです（このスキルだけでも作業できるよう、要点を下に書きます）。

## 最初に決めること（依頼に無ければ聞く）

- 機能名と、見終わった人ができるようになること（1 文）
- 参考ドキュメント、使うリポジトリ（`@natt-cog/<repo>`）、OS
- 本当に新しい作業内容（デモリポジトリの既存機能を確認し、すでにある機能を「作った」ように見せない）

## 共通ルール（要点）

- 画面上の文字はすべて日本語（Noto Sans JP）。ナレーション・BGM・効果音なし。毎回新規録画。
- 実在する機能・実際の結果だけを見せる。テストしていないものを合格と書かない。時系列を変えない。バグを仕込むなら事前許可と字幕での明示。
- Natt の組織と `natt-cog/*` で録画し、メールを `MASK_TEXT` で隠す。

## 手順

1. **計画:** ドキュメントを読み、6〜12 カットのショットリストを書く。1 カット = 1 操作 + 1 行の字幕。手順が長い場合は 2〜4 章に分け、各章の頭に章カードを置く。
2. **アカウントの準備:** 過去のテイク・開いている PR・オートメーション・Memory に、話の邪魔になる古い状態が無いか確認する。アーカイブ・削除・Memory の編集・マージは Natt の許可を取ってから行い、許可された分だけにする。
3. **録画:** CDP（`127.0.0.1:9333`）でサインイン済みの Chrome を操作し、カットごとにスクリーンショットを撮る（`_kit/capture/rec.mjs` の `goto`・`click`・`type`・`poll`・`shot`）。ライトモード、倍率 125%、不要なサイドバー・右パネルは閉じる。通知・バナー・読み込み中の画面・本物の秘密情報が写らないようにする。
4. **編集（`spec.js`）:** `hold`、`skip`、字幕の上書き、`"badge": "早送り"`、章カード（`chapter`）を設定する。編集だけの修正は録画し直さず `spec.js` を直して再ビルドする。字幕の修正は `spec.js` と `capture.mjs` の両方に入れる。
5. **書き出し:** `videos/` で `bash _kit/tools/build.sh <folder>`（無音の 4K60 と 1080p）。全体をビルドする前に `render.mjs --frames` で静止画を確認する。
6. **見直し:** 数秒ごと・字幕ごと・章カードごとにフレームを確認し、直してから再ビルドする。

## 操作はすべて本物にする

- 字幕が「X をクリック」なら、実際に X をクリックし、スクリプトで結果を確認する。確認できなければその撮影は失敗にする。
- 対象は実際の DOM 要素と位置で探す。似た文字列の別要素を拾わない。`r.find({text})` には文字列を渡す（正規表現は不可）。
- すでに画面に出ている結果を「開く」操作は見せない。一度戻してから実際に開く。
- 実際の UI が出るまで `p.evaluate(...)` と短い `sleep` で待つ。ホームの入力欄は `main [contenteditable]` が出てから操作する。コマンドパレットは常に隠れた `[role=dialog]` があるので、表示されているか確認する。
- セッションは 1 回だけ開始する。リトライで重複したら止めてアーカイブする。
- Devin の Computer タブで作業中は録画用カーソルを隠す（`cursor: false`）。

## 編集のポイント

- 作業中の待ちは 2〜2.5 秒、無操作は 3 秒以内。`poll` は「実際の間隔 ÷ `speed`」の長さになるので、飛ばした範囲の直前の `poll` には `hold` を付ける。`render.mjs <folder> --count` で長さを確認する。
- セッションに入ったら画面全体を見せる（`noZoom`）。カーソルが読ませたい文字を隠さないようにする。
- 字幕は 30 文字前後、です・ます調、画面で見えることだけ。メニューや設定画面では部品の近く（`capPos: 'auto'` + `target`）、セッション内は入力欄にかからない位置。
- 大事なメニューやダイアログは 2.5〜3 秒見せる。リングは細い青 1 つ、表示後に出して短く消す。
- 機能に複数のモード（トリガーの種類など）がある場合は、最初に短く一覧を見せてから 1 つを詳しく見せる。Devin が設定を自動生成できる場合（Generate with Devin など）は、手入力ではなくそれを見せる。
- 最後は動いている結果（PR、テスト録画、動くアプリなど）で終え、「すぐ試せる」ボタンがあれば示す。

## 機能別の注意

- **テスト・録画:** テストが終わるまで待ち、合格した録画だけを結果として見せる。失敗した場合は実際の修正と再テストを見せるか、原因を直して撮り直す。
- **Devin Review:** 実際に出た指摘を使い、修正のコミットと「Resolved」までを見せる。
- **Managed Devins / Boards:** 実際の子セッションの分岐と結果を見せる。最終的な件数を字幕に書く（計画段階の数ではなく）。
- **Memory / Skills:** 設定画面（Customize）を見せ、新しいセッションで実際に反映される様子を見せる。
- **Code Scans / Security Swarm:** 実際の指摘から Fix with Devin、PR までを見せる。検出範囲を誇張しない。
- **Windows・OutSystems・Databricks・Slack:** 実際の環境・連携で動かす。使えない場合は Natt に確認し、画面を作らない。

## 書き出し・確認・納品

`ja-devin-overview-video` の「書き出しと確認」「納品」と同じ。`ffprobe` で音声ストリームが無いこと、3840×2160・60fps を確認し、`natt-cog/devin-demo-videos` に PR を出す。Natt の許可なくマージしない。
